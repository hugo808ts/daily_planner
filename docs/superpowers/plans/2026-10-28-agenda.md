# Agenda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build "Agenda", a personal pt-BR week/day organizer with AI quick capture and an Ideas notebook, running free on Cloudflare (Workers + D1 + Workers AI + Access), usable as an iPhone home-screen app and on desktop.

**Architecture:** One Cloudflare Worker serves the Vite/React build as static assets and a Hono API under `/api/*`. Data lives in D1 (SQLite). Pure, shared logic (dates, task status, capture rules, weekly report) lives in `shared/` and is imported by both Worker and UI, so it is unit-tested once. The UI is one responsive React app: two tabs on mobile, a three-pane layout on desktop.

**Tech Stack:** TypeScript, React 19, Vite + `@cloudflare/vite-plugin`, Tailwind CSS 4, Hono 4, Zod 4, `jose` (Access JWT), Wrangler 4, Vitest (+ `@cloudflare/vitest-pool-workers` for Worker/D1 tests), Playwright for end-to-end. Fonts: `@fontsource-variable/bricolage-grotesque`, `@fontsource-variable/geist`.

**Spec:** `docs/superpowers/specs/2026-10-28-agenda-design.md` (approved 28/10/2026). Mockups: `docs/superpowers/mockups/` (the spec wins where they differ).

## Global Constraints

- All UI copy in Brazilian Portuguese.
- Zero cost: only free-plan Cloudflare features; never call a paid API; when a limit fails, degrade (rules instead of AI, clear error), never crash.
- Time zone `America/Sao_Paulo` for "today", "now", overdue and day boundaries — on server and client alike. Task dates are calendar strings `YYYY-MM-DD`; times are `HH:MM` or null.
- Areas: `work` (💼 Trabalho), `school` (📚 Faculdade), `personal` (❤️ Pessoal), or null.
- Score week = Monday–Saturday; Sunday tasks show on their day but never count. Weekly summary card shows on Sunday.
- Task done at any time (even after its time) = plain done, no lateness mark.
- Nothing moves day automatically. Moving a task that is not yet "not done" changes its date; moving a "not done" task leaves it recorded and creates a copy with `moved_from_id`.
- One capture message = one item. Confirmation sheet always shown before saving.
- Every idea belongs to a folder; folders are user-created, one level, none pre-seeded.
- Resolving an idea deletes it after confirmation, with a 5 s "Desfazer" toast.
- One link per idea; previews only for TikTok and YouTube oEmbed.
- Capture text: trimmed, 1–500 chars. Audio: ≤ 60 s and ≤ 5 MB. Task title 1–160 chars; idea title 1–160, body ≤ 20 000; folder name 1–40; day note ≤ 300.
- AI model: `@cf/meta/llama-3.1-8b-instruct` with `response_format: { type: "json_schema" }`; transcription: `@cf/openai/whisper-large-v3-turbo`, language `pt`.
- iPhone/PWA: input font-size ≥ 16 px, touch targets ≥ 44 px, safe-area insets, standalone manifest, apple-touch-icon. Follow the `mobile-native` skill.
- Design tokens: background `#F3F1FA`, ink `#24203A`, accent `#6D4AFF`, danger `#E5484D`, note `#FFF6C9`; fonts Bricolage Grotesque (display) + Geist (text), bundled locally; dark mode follows the system.
- Every `/api/*` request requires a valid Cloudflare Access JWT, except when `env.DEV === "true"` (local only). Mutations reject cross-origin requests.

## Review Focus

1. **Day rollover across UTC:** at 23:30 in São Paulo it is already the next day in UTC; "today", overdue and "not done" must use São Paulo time. (Task 3 test `todayISO handles UTC rollover`.)
2. **AI returns junk:** a past date, an impossible date, an unknown area, a folder id that does not exist, or invalid JSON. Expected: fields sanitized to null/defaults, never a crash, never a save without confirmation. (Task 7 tests.)
3. **Empty, whitespace-only or very long capture text, and oversized audio from the iPhone** (`audio/mp4`). Expected: clear 400/413 in Portuguese. (Tasks 7 tests.)
4. **Closing the app during the 5 s undo window:** the user already confirmed, so the idea must stay deleted, and "Desfazer" must restore it intact (same id, folder, pinned, link). Expected: delete happens immediately server-side; undo re-creates from the saved copy. (Task 5 test `restore recreates the idea exactly`.)
5. **Marking a task done after its time passed, or un-marking it later:** status must flip between overdue/done/not-done correctly, and past weeks must not change when a not-done task is moved. (Task 3 and Task 4 tests.)
